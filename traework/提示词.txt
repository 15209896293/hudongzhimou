## 架构目标

重构后，数据流应该是：

VideoThread(QThread) → AppController.on_frame_received() → FramePipeline.process_frame()
  → Stage1: Inference（推理跳帧）
  → Stage2: Counter（动作计数）
  → Stage3: Safety（安全检测，每3帧一次）
  → Stage4: Render（骨架绘制→镜像→角度线→BGR→RGB）
→ FramePipeline.frame_rendered 信号 → VideoDisplay.update_image()

UI信号 → AppController.on_xxx() → Manager → AppState → 信号通知UI更新

## 6条必须遵守的关键约束

1. 【安全检测节流计数器必须在 FramePipeline 顶层管理】
   FramePipeline._safety_frame_counter 在 process_frame() 入口每帧递增，不能放在 _stage_safety() 内部。否则检测频率会从每100ms降到每200ms。

2. 【mirror_mode 变更时必须同时更新 VideoThread】
   video_processor.toggle_mirror() 内部必须调用 video_thread.set_mirror()，不能只更新 AppState。

3. 【推理跳帧计数器初始值保持为1】
   FramePipeline._inference_frame_counter = 1，确保首帧必推理，触发模型延迟加载。

4. 【ModeManager 保留对 main_window 的布局操作引用】
   switch_to_workout_mode() 和 switch_to_stats_mode() 中的布局操作需要 main_window，不要移除这个引用。

5. 【设备/模型切换的回滚逻辑必须覆盖所有相关组件】
   change_device() 和 change_model() 的回滚要确保 VideoThread、PoseProcessor、AppState 三者同步回滚。

6. 【VideoThread 的 current_inference_frame 写入目标改为 AppState】
   把 self.main_window.current_inference_frame 改为 self.app_state.current_inference_frame。
