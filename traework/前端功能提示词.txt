# 功能1：用户档案面板（最高优先级）
# 适合先做，为后续"个性化安全阈值"功能打下基础

```
请在 Good-GYM 桌面端项目中新增一个"用户档案面板"功能。

## 项目位置
f:\比赛\护动智眸\大创赛\Good-GYM\Good-GYM\

## 功能需求

在控制面板下方新增一个可折叠的"用户档案"面板，让用户录入个人身体信息和运动损伤史，为后续的"个性化安全阈值调整"功能提供数据基础。

## 具体要求

### 1. 新建文件 ui/user_profile_panel.py

创建一个可折叠的用户档案面板组件，包含以下表单项：

- 姓名（文本输入，可选）
- 性别（下拉选择：男/女）
- 年龄（数字输入）
- 身高（数字输入，单位cm，范围100-250）
- 体重（数字输入，单位kg，范围30-200）
- 损伤史（多选框，可多选）：
  - 左膝关节损伤
  - 右膝关节损伤
  - 腰椎/下背部损伤
  - 左肩关节损伤
  - 右肩关节损伤
  - 颈椎损伤
  - 无损伤史（默认选中）

- 一个"保存档案"按钮
- 一个"重置表单"按钮

### 2. 数据存储

创建 data/user_profiles.json 文件，结构如下：
```json
{
  "current_user": "default",
  "users": {
    "default": {
      "name": "",
      "gender": "",
      "age": null,
      "height": null,
      "weight": null,
      "injury_history": [],
      "created_at": "2026-07-02"
    }
  }
}
```

### 3. UI设计要求

- 面板风格与现有 ui/styles.py 中的暗色主题保持一致
- 使用 AppStyles.get_group_box_style() 保持视觉统一
- 面板默认折叠，点击标题栏展开/收起
- 表单布局紧凑，不占用过多空间
- 保存成功后显示绿色提示文字（用QLabel，2秒后消失）

### 4. 信号定义

```python
# 用户档案面板发出的信号
profile_saved = pyqtSignal(dict)     # 档案保存完成，传出用户数据
profile_loaded = pyqtSignal(dict)    # 应用启动时加载已有档案
```

### 5. 集成方式

在 app/main_window.py（或 app/stats_manager.py）中：
- 应用启动时自动加载 user_profiles.json
- 将用户档案面板添加到右侧区域（控制面板下方）
- 连接 profile_saved 信号

### 6. 国际化

使用 core/translations.py 添加以下翻译键：
- "user_profile": 中文"用户档案" / 英文"User Profile"
- "save_profile": 中文"保存档案" / 英文"Save Profile"
- "reset_form": 中文"重置" / 英文"Reset"
- "name": 中文"姓名" / 英文"Name"
- "gender": 中文"性别" / 英文"Gender"
- "age": 中文"年龄" / 英文"Age"
- "height": 中文"身高(cm)" / 英文"Height(cm)"
- "weight": 中文"体重(kg)" / 英文"Weight(kg)"
- "injury_history": 中文"损伤史" / 英文"Injury History"
- "no_injury": 中文"无损伤史" / 英文"No injuries"
- "left_knee": 中文"左膝关节损伤" / 英文"Left knee injury"
- "right_knee": 中文"右膝关节损伤" / 英文"Right knee injury"
- "lower_back": 中文"腰椎/下背部损伤" / 英文"Lower back injury"
- "left_shoulder": 中文"左肩关节损伤" / 英文"Left shoulder injury"
- "right_shoulder": 中文"右肩关节损伤" / 英文"Right shoulder injury"
- "neck": 中文"颈椎损伤" / 英文"Neck injury"
- "profile_saved": 中文"档案已保存" / 英文"Profile saved"
- "height_weight_required": 中文"请至少填写身高和体重" / 英文"Please enter height and weight"

### 7. 注意事项

- 参考现有 ui/coach_panel.py 的面板风格和折叠实现方式
- 参考现有 ui/control_panel.py 的组件布局方式
- 数据文件读写参考 core/workout_tracker.py 的JSON操作模式
- 如果 data/user_profiles.json 不存在，首次保存时自动创建，包含默认空档案
- 不要修改任何现有功能代码，只新增文件和做最小化的集成
- 表单验证：身高和体重为必填项，保存时检查
```

# 功能2：对比演示面板（比赛答辩杀手锏）

```
请在 Good-GYM 桌面端项目中新增一个"对比演示模式"，用于比赛现场直观展示护动智眸与普通健身App（如Keep）的差异。

## 项目位置
f:\比赛\护动智眸\大创赛\Good-GYM\Good-GYM\

## 功能需求

在菜单栏的"模式"菜单下新增一个"对比演示模式"，进入后左侧显示"普通计数模式"（只有骨架+计数），右侧显示"护动智眸模式"（骨架+计数+安全检测+语音提醒），让观众直观看到差异化。

## 具体要求

### 1. 新建文件 ui/comparison_panel.py

创建一个左右分屏的对比面板：

**左半屏（普通模式 - 对标Keep）：**
- 视频显示区域（显示摄像头画面+骨架）
- 计数器数字
- 运动类型名称
- 标题标签："普通计数模式"（灰色文字，无亮点）

**右半屏（护动智眸模式）：**
- 视频显示区域（显示同一摄像头画面+骨架+角度线）
- 计数器数字
- 运动类型名称
- 安全状态指示灯（绿/黄/红）
- 实时安全建议文字
- 语音提醒状态
- 标题标签："护动智眸 - AI防伤模式"（高亮文字，品牌色）

**中间分隔线：**
- 竖线分隔
- 顶部显示 "VS" 文字

### 2. 新建文件 app/comparison_manager.py

创建对比模式管理器，负责：
- 管理对比模式的生命周期（进入/退出）
- 左右两个视频显示区域的布局管理
- 左侧只做计数（调用 exercise_counter，但不调用 safety_detector）
- 右侧做完整流程（调用 exercise_counter + safety_detector + sound_manager）
- 共享同一个 VideoThread 的帧数据

### 3. 信号定义

```python
class ComparisonManager(QObject):
    comparison_started = pyqtSignal()
    comparison_stopped = pyqtSignal()
```

### 4. 集成方式

在 app/main_window.py 中：
- 菜单栏"模式"菜单新增"对比演示模式"选项
- 进入对比模式时隐藏现有布局，显示 comparison_panel
- 退出对比模式时恢复现有布局
- 参考现有 mode_manager.py 中 switch_to_workout_mode() 和 switch_to_stats_mode() 的布局切换逻辑

### 5. 帧处理逻辑

对比模式下的帧处理：
1. VideoThread 正常采集帧
2. 帧数据同时传递给左右两个处理路径：
   - 左侧：只做骨架绘制 + 计数（不调用安全检测）
   - 右侧：完整流程（骨架 + 计数 + 安全检测 + 渲染安全状态叠加文字）
3. 左右两个 VideoDisplay 实例分别显示各自的处理结果

### 6. UI设计要求

- 左右两个视频区域等宽，各占50%
- 右侧面板的安全状态指示灯使用 coach_panel.py 中已有的安全状态样式
- 右侧面板在检测到 WARNING/DANGER 时，视频画面上叠加红色半透明警告边框
- 整体风格与现有暗色主题保持一致

### 7. 国际化

使用 core/translations.py 添加以下翻译键：
- "comparison_mode": 中文"对比演示模式" / 英文"Comparison Mode"
- "normal_counting": 中文"普通计数模式" / 英文"Normal Counting"
- "ai_safety_mode": 中文"护动智眸 - AI防伤模式" / 英文"Hu Dong Smart Eyes - AI Safety Mode"

### 8. 注意事项

- 参考现有 app/mode_manager.py 的布局切换实现
- 参考现有 ui/coach_panel.py 的安全状态指示灯实现
- 参考现有 ui/video_display.py 的视频显示实现
- 左右两侧必须共享同一个 exercise_counter 实例（保证计数一致）
- 左侧可以单独创建一个精简的 pose_processor 实例（只做推理，不做安全检测）
- 不要修改任何现有功能代码，只新增文件和做最小化的菜单集成
- 进入对比模式时，原始控制面板和安全面板隐藏
```
