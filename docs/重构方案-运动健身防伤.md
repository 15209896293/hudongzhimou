## 一、项目定位

**一句话定义**：基于浏览器实时姿态识别的运动健身防伤评估系统，以 FMS（功能性运动筛查）为核心，帮助用户在训练中识别受伤风险、纠正动作模式。

**核心价值**：
- 不是"计数器"，而是"防伤筛查器"
- 不需要安装桌面软件，浏览器打开即用
- AI 视觉分析 + 规则引擎双轨交叉验证

**目标用户**：健身爱好者、运动初学者、康复训练人群

## 四、FMS 评分体系

### 4.1 七项筛查动作

| 编号 | 动作名称 | 英文名 | 关注要点 | 评分标准 |
|------|----------|--------|----------|----------|
| 1 | 深蹲 | Deep Squat | 膝关节屈曲、躯干前倾、足跟着地 | 0-3 分 |
| 2 | 跨栏步 | Hurdle Step | 髋关节屈曲、平衡、足部对齐 | 0-3 分 |
| 3 | 直线弓步 | In-Line Lunge | 膝关节屈曲、脊柱稳定、骨盆水平 | 0-3 分 |
| 4 | 肩关节灵活性 | Shoulder Mobility | 肩关节内旋/外旋、双侧对称 | 0-3 分 |
| 5 | 主动直腿抬高 | Active Straight-Leg Raise | 髋关节屈曲、腘绳肌柔韧性 | 0-3 分 |
| 6 | 躯干稳定性俯卧撑 | Trunk Stability Push-Up | 躯干稳定、肩关节力量 | 0-3 分 |
| 7 | 旋转稳定性 | Rotary Stability | 躯干旋转、四肢协调 | 0-3 分 |

### 4.2 评分标准

| 分数 | 含义 | 描述 |
|------|------|------|
| 3 | 完美 | 动作标准完成，无代偿 |
| 2 | 合格 | 动作完成但有轻微代偿 |
| 1 | 不合格 | 动作无法标准完成 |
| 0 | 疼痛 | 动作过程中出现疼痛 |

**总分**：0-21 分
- **≥18 分**：受伤风险低
- **14-17 分**：受伤风险中等
- **<14 分**：受伤风险高，建议专业评估
- **任何单侧不对称（左右差>0）**：即使总分≥14 也视为风险

### 4.3 MediaPipe 关键点映射

MediaPipe 提供 33 个 3D 关键点，FMS 评分需要的关键关节：

```
// 关键关节索引（MediaPipe Pose 33 点）
const KEYPOINTS = {
  NOSE: 0,
  LEFT_SHOULDER: 11, RIGHT_SHOULDER: 12,
  LEFT_ELBOW: 13, RIGHT_ELBOW: 14,
  LEFT_WRIST: 15, RIGHT_WRIST: 16,
  LEFT_HIP: 23, RIGHT_HIP: 24,
  LEFT_KNEE: 25, RIGHT_KNEE: 26,
  LEFT_ANKLE: 27, RIGHT_ANKLE: 28,
  LEFT_FOOT_INDEX: 31, RIGHT_FOOT_INDEX: 32
};

// 需要计算的关节角度
const ANGLES = {
  kneeFlexion:      [HIP, KNEE, ANKLE],       // 膝关节屈曲
  hipFlexion:       [SHOULDER, HIP, KNEE],     // 髋关节屈曲
  trunkInclination: [SHOULDER, HIP, 垂直线],    // 躯干前倾角
  shoulderMobility: [腕间距 / 上臂长度],         // 肩关节灵活性
  pelvicTilt:       [左髋-右髋 水平偏差],        // 骨盆倾斜
  ankleDorsiflexion:[KNEE, ANKLE, FOOT_INDEX]  // 踝关节背屈
};
```

## 五、系统架构

### 5.1 四阶段处理管线

```
摄像头帧 → [1.推理] → [2.FMS分析] → [3.防伤检测] → [4.渲染]
              │            │              │             │
         MediaPipe     评分引擎      规则引擎      Canvas绘制
         33个关键点    0-3分/动作    风险预警      骨架叠加
```

**阶段 1 — 推理（Inference）**
- MediaPipe Tasks Web API 实时检测 33 个 3D 关键点
- 输出：`{ keypoints: [{x, y, z, visibility}, ...], timestamp }`

**阶段 2 — FMS 分析（Analysis）**
- 根据当前动作类型，计算相关关节角度
- 对照 FMS 评分标准，给出 0-3 分
- 输出：`{ score, issues: [...], recommendations: [...] }`

**阶段 3 — 防伤检测（Safety Detection）**
- 检测膝关节内扣（knee valgus）
- 检测骨盆倾斜（pelvic tilt）
- 检测躯干过度前倾（trunk inclination）
- 检测左右不对称（asymmetry）
- 输出：`{ level: 'safe'|'warning'|'danger', alerts: [...] }`

**阶段 4 — 渲染（Rendering）**
- Canvas 叠加彩色骨架线
- 实时显示关节角度
- 风险等级颜色编码（绿/黄/红）
- 输出：可视化画面

### 5.2 前后端交互

```
浏览器                              Node.js 后端
┌─────────────────┐                ┌──────────────────┐
│  MediaPipe 推理  │                │  Express API     │
│  (本地浏览器)    │                │                  │
│                  │   REST API     │  用户认证        │
│  FMS 评分引擎   │ ←──────────→   │  训练记录存储    │
│  (本地 JS)       │                │  AI 分析服务     │
│                  │                │  (GLM-4V/4Flash) │
│  防伤规则引擎   │                │                  │
│  (本地 JS)       │                │  MySQL 数据库    │
└─────────────────┘                └──────────────────┘
```

**设计原则**：姿态识别和 FMS 评分在浏览器本地完成（零延迟），AI 深度分析和数据持久化走后端 API。

## 八、AI 分析双轨制

### 8.1 文本分析轨（GLM-4-Flash）

**输入**：关节角度序列 + 动作类型 + 用户伤病历史
**输出**：JSON 格式的动作评估和建议

```json
{
  "score_adjustment": 0,
  "issues": [
    {
      "joint": "knee",
      "side": "left",
      "problem": "膝关节内扣",
      "severity": "moderate",
      "angle": 12
    }
  ],
  "recommendations": [
    "加强臀中肌训练，改善膝关节外翻",
    "深蹲时注意膝盖与脚尖方向一致"
  ]
}
```

### 8.2 视觉分析轨（GLM-4V-Flash）

**输入**：关键帧截图（Base64）+ 动作类型 + 当前评分
**输出**：JSON 格式的视觉评估

```json
{
  "posture_quality": "fair",
  "observed_issues": [
    "躯干过度前倾",
    "右膝内扣"
  ],
  "score_estimate": 2,
  "coaching_tip": "尝试保持 chest up，膝盖追踪脚尖方向"
}
```

### 8.3 交叉验证

- 两轨评分差 ≤ 1：采用较高分
- 两轨评分差 = 2：标记为"需人工确认"
- 两轨评分差 = 3：触发警报，建议重新测试

## 十、关键风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| MediaPipe 在低配设备卡顿 | 体验差 | 提供模型精度选择（Lite/Full），降帧策略 |
| FMS 评分准确率不足 | 专业性质疑 | 参考 FMS 官方评分标准，AI 双轨交叉验证 |
| 浏览器兼容性问题 | 无法演示 | 限定 Chrome/Edge 90+，提供兼容性检测 |
| AI API 不可用 | 功能缺失 | 本地规则引擎作为 fallback，不依赖 AI 也能基本工作 |
| 比赛现场网络不稳定 | AI 分析失败 | 核心功能（姿态识别+FMS评分）完全本地化，AI 仅增强 |
